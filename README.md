# bc2regbot — бот участника Business Cup 2.0

Telegram-бот регистрации, коммуникации и чекина для Business Cup 2.0 (Zimran x AIESEC, 14–15 ноября,
Nazarbayev University, Астана). Пускает только отобранных, привязывает Telegram по персональной
ссылке, рассылает новости и опрос явки, отмечает на входе по меняющемуся QR и сообщает боту игр
([bchbot](https://github.com/ewalovespewa-cmyk/bchbot)), кто активировал бота и кто пришёл.

> ⚠️ **Ровно один инстанс.** Webhook, фоновые воркеры (рассылки, напоминания, синхронизация) и
> лимиты рассчитаны на один процесс. На Railway — 1 реплика, не увеличивай.

## Как устроено
```
Telegram ──webhook──▶ aiohttp ─┬─ /tg/webhook          aiogram: дедуп update_id → сессия БД → роутеры
                               ├─ /health              Postgres + Redis (healthcheck Railway)
                               ├─ /checkin-screen      экран у входа: QR меняется каждые 30 с
                               ├─ /dashboard           цифры, график, команды
                               ├─ /webapp/scan         Mini App «Отметиться» (сканер QR)
                               └─ /api/…               статус участника для бота игр
                фоновые задачи (под лидер-локом в Redis): рассылки · напоминания опроса ·
                outbox → бот игр · автоимпорт и bot_status в Google Sheet
Postgres — единственный источник правды; Redis — FSM, дедуп апдейтов, лимиты, лок воркеров.
```
- **Стек:** Python 3.12, aiogram 3, aiohttp, SQLAlchemy 2 async + Alembic, Redis, structlog (JSON-логи).
- **Надёжность:**
  - всё состояние в Postgres и Redis, рестарт ничего не теряет;
  - повторно доставленный апдейт не обрабатывается дважды;
  - ошибка показывает пользователю вежливое сообщение и шлёт трейсбек в чат организаторов (с троттлингом);
  - на все внешние вызовы стоят таймауты;
  - Google Sheets вызывается в фоне с ретраями, его падение бота не ломает.

### Путь участника
1. **Импорт.** Отобранные импортируются из таблицы заявок (`/import`). Каждый получает ссылку
   `t.me/<бот>?start=<токен>`, которая пишется на лист `bot_status` (или в `/export`). Письма
   отправляет команда, не бот.
2. **Привязка.** Участник открывает ссылку, бот привязывает Telegram. Если открыл бота без ссылки,
   бот сначала тихо сверяет его Telegram username с username из заявки и при однозначном совпадении
   привязывает сразу, ничего не спрашивая. Только если не совпало, бот просит «Поделиться контактом»
   и сверяет номер. Остальным бот вежливо отказывает и даёт контакт организатора.
3. **До проекта.** Меню («Мой статус», «Расписание», «Локация», «FAQ», «Контакты», «Задать вопрос»,
   язык ru/en), рассылки, опрос «Придёшь?» с напоминаниями, выгрузка на обзвон.
4. **На входе.** Человек сканирует QR на экране камерой или кнопкой «✅ Отметиться» и получает
   «✅ Ты отмечен! День N. Команда X: 2/3 на месте» и кнопку «🎲 Открыть бинго». Если номер не совпал,
   есть кнопка «Позвать организатора», и волонтёр отмечает вручную через `/find`.

## Админка на кнопках
Роли: **superadmin** (ID из `SUPERADMIN_IDS`), **admin**, **volunteer**. Админ или волонтёр открывает
бота и нажимает `/start` (или кнопку «🛠 Админка»), после чего получает меню кнопками. Набирать
команды не нужно:

| Раздел | Кто | Кнопки |
|---|---|---|
| 👥 Участники | admin+ | импорт отобранных / всех / команд из файла (CSV или Excel), импорт из Google Sheet, «📊 Выгрузить Excel», «🔄 Обновить Google Sheet», автоимпорт вкл/выкл |
| ✅ Чекин | admin+ | открыть или закрыть чекин сегодня, экран вкл/выкл, статистика по командам, «📅 Дни» (добавить, изменить, удалить день), «🧹 Сбросить отметки» (суперадмин), ссылки на экран QR и дашборд |
| 📣 Рассылки и опрос | admin+ | новая рассылка, последние рассылки и отмена, запуск, сводка и закрытие опроса, список на обзвон, опрос по командам |
| 📝 Контент | admin+ | расписание, локация, FAQ, контакты |
| 🔎 Найти участника | volunteer+ | поиск и карточка: «✅ Отметить сегодня», «📞 Результат обзвона», «🔓 Отвязать Telegram» |
| ⚙️ Команда бота | superadmin | добавить или убрать админа и волонтёра, журнал действий, подозрительное |

**Импорт файлом.** Достаточно прислать боту файл (CSV или Excel), и он спросит, что с ним сделать:
импортировать отобранных, всех строк или назначить команды.

**🧹 Сброс отметок (для тестов).** Можно сбросить отметки за сегодня или за все дни, перед этим бот
спросит подтверждение. Участники смогут отметиться заново, а в боте игр у них снова закроется бинго.
Привязки к боту и ответы на опрос сброс не трогает. Тестовый день удаляется кнопкой «🗑» в «📅 Дни».

Вопросы участников приходят в чат организаторов с кнопкой «✍️ Ответить». Админ отвечает reply-ем,
ответ уходит участнику.

### Сегменты рассылок
- все привязанные;
- по опросу: «Приду», «Не смогу», «Не знаю», не ответили;
- по чекину: отмечены в день N, не отмечены в день N;
- **«Ждём тебя»**: ответили «Приду», но не отметились;
- конкретная команда, соло;
- тест «только мне».

В тексте можно писать `{name}`: бот подставит имя участника. `TEST_MODE=true` отправляет любые
рассылки только админам.

### Движок рассылок
- **Скорость** не выше 25 сообщений в секунду.
- **Ошибки:** на 429 бот ждёт `retry_after` и повторяет, на 403 помечает «заблокировал бота»,
  остальные ошибки повторяет до 3 раз.
- **Получатели** фиксируются в момент запуска. Строки захватываются через `SKIP LOCKED`.
- **После рестарта** рассылка продолжается с места остановки, отправленным повторно не уходит.
- **Отчёт** (отправлено / заблокировали / ошибки) получает создатель и чат организаторов.

## Деплой на Railway (пошагово)
Проект Railway — **bchbot**, в нём живут оба бота, Postgres и Redis.

1. **Сервисы.**
   - Postgres: `+ New → Database → PostgreSQL`.
   - Redis: `+ New → Database → Redis`.
   - Бот: `+ New → GitHub Repo → ewalovespewa-cmyk/bc2regbot`, ветка `main`.
2. **Настройки сервиса бота** (Settings):
   - Builder — Dockerfile (из репозитория);
   - Pre-deploy command — `alembic upgrade head` (миграции до переключения трафика);
   - Healthcheck path — `/health`, timeout 120;
   - Restart policy — On Failure, 10 попыток;
   - **Replicas — 1**;
   - Networking → Generate Domain (порт 8080).

   Эти настройки описаны и в [.railway/railway.ts](.railway/railway.ts) (Infrastructure as Code).
   `railway.json` Railway больше не применяет к новым сервисам.
3. **Переменные** (Variables), полное описание в [.env.example](.env.example):

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от @BotFather (секрет, вставить вручную) |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
   | `REDIS_URL` | `${{Redis.REDIS_URL}}` |
   | `WEBHOOK_BASE_URL` | `https://${{RAILWAY_PUBLIC_DOMAIN}}` |
   | `PORT` | `8080` |
   | `WEBHOOK_SECRET`, `CHECKIN_SECRET`, `SCREEN_SECRET`, `DASHBOARD_SECRET`, `INTEGRATION_TOKEN`, `GAMIFICATION_WEBHOOK_SECRET` | случайные строки: `python -c "import secrets; print(secrets.token_urlsafe(32))"` |
   | `SUPERADMIN_IDS` | Telegram ID через запятую (узнать: @userinfobot) |
   | `ADMIN_CHAT_ID` | ID чата организаторов; узнать: добавить бота в группу и написать `/chatid` |
   | `ORGANIZER_CONTACT` | контакт для отказов и раздела «Контакты» |
   | `TEST_MODE` | `true` на время репетиций, `false` на мероприятии |
   | `GAMES_BOT_USERNAME`, `GAMES_CHAT_LINK`, `GAMIFICATION_WEBHOOK_URL` | см. [Интеграция с ботом игр](#интеграция-с-ботом-игр) |
   | `SHEET_*`, `GOOGLE_SERVICE_ACCOUNT_JSON` | см. [Google Sheets](#google-sheets-service-account) |
4. **Деплой.** Railway пересобирает бота при каждом push в `main`. При старте бот сам ставит
   webhook на `WEBHOOK_BASE_URL/tg/webhook` с `secret_token` и проверяет заголовок
   `X-Telegram-Bot-Api-Secret-Token`.
5. **Проверка.** `https://<домен>/health` отвечает `{"status":"ok","db":"ok","redis":"ok"}`. В логах
   есть строки `bot_started`, `webhook_set`, `admin_chat_ok`, `scheduler_leadership`.

## Google Sheets (service account)
**Как устроена таблица.** Бот работает с одной Google-таблицей, например «Business Cup 2.0 — кандидаты»:

| Вкладка | Кто ведёт | Что в ней |
|---|---|---|
| 1. «Кандидаты» | команда | все заявки с сайта (бот её не трогает) |
| 2. «Прошли отбор» | команда | те же строки в **том же формате**, только прошедшие. **Есть строка — есть доступ к боту**, убрали строку — доступ закрыт. Колонка «Состояние» тут не важна |
| 3. «Статус бота» | бот | все прошедшие: ID заявки, имя, почта, телефон, команда, роль, **ссылка-приглашение**, открыл ли бота, ответ на опрос, время чекина по дням |
| 4. «Чекин День 1» | бот | кто отметился в первый день: время, имя, команда, телефон, способ (QR, волонтёр, админ) |
| 5. «Чекин День 2» | бот | то же на второй день |

**Как работает синхронизация:**
- Бот забирает «Прошли отбор» **каждую минуту**. Автоимпорт включён по умолчанию, выключить можно в «👥 Участники».
- Новые люди сразу получают доступ и ссылку, она появляется в «Статус бота».
- Вкладки «Статус бота» и «Чекин …» бот перезаписывает каждые `SHEET_SYNC_MINUTES` минут (по умолчанию 2)
  и по кнопке «🔄 Обновить Google Sheet».
- Колонки бот понимает без настройки: «Имя», «Почта», «Phone number», «Telegram», «Team name»,
  «Position in team», «ID заявки» и т. д. Повторные заявки одного человека схлопываются, берётся последняя.
- **Защита.** Если из «Прошли отбор» разом пропало много людей (больше трети, минимум 10), бот
  решит, что вкладку случайно очистили. Доступ он не закроет и пришлёт предупреждение в чат организаторов.

**Подключение:**
1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект → **APIs & Services →
   Enable APIs** → включить **Google Sheets API**.
2. **IAM & Admin → Service Accounts → Create**. Ключ: **Keys → Add key → JSON**, скачается файл.
3. Открыть таблицу → **Поделиться** → вставить `client_email` из JSON (вида
   `…@….iam.gserviceaccount.com`) → роль **Редактор**. Редактор нужен, чтобы бот вёл свои вкладки.
4. Переменные на Railway:
   - `SHEET_ID` — часть ссылки между `/d/` и `/edit`;
   - `GOOGLE_SERVICE_ACCOUNT_JSON` — содержимое JSON целиком, одной строкой (или base64);
   Остальное по умолчанию уже подходит: источник — вкладка «Прошли отбор», бот пишет в «Статус бота».
5. Проверка в боте:
   - «👥 Участники → 🔄 Забрать «Прошли отбор» сейчас» показывает отчёт;
   - «🔄 Обновить Google Sheet» создаёт вкладки «Статус бота» и «Чекин …».

Пока Sheets не подключён, всё работает через файлы: присылаешь боту таблицу (CSV или Excel), а
забираешь «📊 Выгрузить Excel» с теми же вкладками. Пример: [samples/applications_example.csv](samples/applications_example.csv).

**Импорт идемпотентен.**
- Ключ — email в нижнем регистре. Повторный импорт обновляет поля, не создаёт дублей и **не меняет
  выданные ссылки**.
- Если у человека «Состояние» сменилось с «Прошёл отбор» на другое, бот перестаёт его пускать.
- Телефоны приводятся к E.164 (`8 (776) 920-46-59` → `+77769204659`). Номер в поле Telegram бот
  отбрасывает, username сохраняется без `@`.

## Экран чекина и дашборд
- **Экран:** `https://<домен>/checkin-screen?key=<SCREEN_SECRET>`. Открыть на ноутбуке у входа на весь экран (F11).
  - QR кодирует `t.me/<бот>?start=ci_<код>`. Код — HMAC от секрета, дня и 30-секундного окна;
    принимаются текущее и предыдущее окно.
  - Страница сама обновляет QR и показывает отсчёт и «отмечено X из Y».
- **Дашборд:** `https://<домен>/dashboard?key=<DASHBOARD_SECRET>`. Обновляется сам каждые 10 секунд.
  Показывает отмеченных, команды в полном составе, частично и без единого отмеченного, график по
  10 минутам, таблицу команд с поиском и последние отметки.
- **Ссылки** на экран и дашборд присылает команда `/screen`.
- **Открытие дня:**
  - `/checkin_open` включает чекин сегодня и при необходимости сдвигает окно на «сейчас»;
  - `/checkin_close` выключает его;
  - окна дней задаются в `EVENT_DAYS` или командой `/day`.
- **Защита:**
  - аккаунт отмечает только себя, не больше раза в день;
  - неверные коды ограничены (10 за 10 минут), после этого алерт;
  - всё подозрительное собирается в `/suspicious`;
  - отменить чекин может только admin, отмена пишется в журнал.

## Интеграция с ботом игр
Игры (фотохант, экспедиция) доступны тем, кто активировал этот бот. **Бинго** доступно только
отметившимся на входе. Со стороны бота игр это слой `integration/` в
[bchbot](https://github.com/ewalovespewa-cmyk/bchbot/tree/main/integration), его функции игр не менялись.

- **API** (заголовок `Authorization: Bearer <INTEGRATION_TOKEN>`):
  - `GET /api/participant-status?telegram_user_id=…` → `{activated, participant_id, full_name, team, checkins:[{day, at}], checked_in_today}`;
  - `GET /api/checkin-status?telegram_user_id=…&day=YYYY-MM-DD` → `{checked_in, at}`.
- **Исходящий webhook.** При привязке, отвязке и чекине (и его отмене) бот делает POST на
  `GAMIFICATION_WEBHOOK_URL`:
  - заголовки `X-BC-Event-Id`, `X-BC-Timestamp`,
    `X-BC-Signature: sha256=HMAC(GAMIFICATION_WEBHOOK_SECRET, "<timestamp>.<body>")`;
  - тело `{"event_id", "type", "created_at", "data": {telegram_user_id, participant_id, team, day, timestamp, …}}`;
  - типы: `participant.linked`, `participant.unlinked`, `checkin.created`, `checkin.cancelled`;
  - событие пишется в outbox в той же транзакции. Если бот игр лежит, доставка повторяется
    (10 с, 20 с, 40 с … до часа) в течение суток, затем приходит алерт.
- **Настройка в Railway:**
  - здесь: `GAMIFICATION_WEBHOOK_URL=http://${{bchbot.RAILWAY_PRIVATE_DOMAIN}}:8080/bc-events`
    и `GAMES_BOT_USERNAME=<username бота игр>`, по желанию `GAMES_CHAT_LINK`;
  - в боте игр: `BC_API_URL=http://${{bc2regbot.RAILWAY_PRIVATE_DOMAIN}}:8080`,
    `BC_API_TOKEN=${{bc2regbot.INTEGRATION_TOKEN}}`,
    `BC_WEBHOOK_SECRET=${{bc2regbot.GAMIFICATION_WEBHOOK_SECRET}}`, `PORT=8080`.

## Локальный запуск и тесты
Нужен Python 3.12. Docker не нужен: тесты сами поднимают встроенный Postgres (`pgserver`, данные
в `.pgdata/`), Redis в тестах — fakeredis.
```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt -e ".[dev]"
.venv/Scripts/python -m pytest -q
```
Запуск бота локально: `cp .env.example .env`, вписать токен **отдельного dev-бота** и `REDIS_URL`,
затем `alembic upgrade head` и `python -m app.main`. Без `WEBHOOK_BASE_URL` бот работает через
polling (он снимает webhook, поэтому боевой токен локально не используй).

Тесты покрывают:
- нормализацию телефонов;
- коды QR на границах окон;
- сегменты;
- идемпотентность импорта;
- привязку и все отказы;
- движок рассылок (429, 403, рестарт, отмена, расписание);
- опрос, чекин и экран;
- API и подпись webhook.

Сценарии в Telegram проверяются настоящими апдейтами через диспетчер (`tests/harness.py`).

## Нагрузочный прогон
```bash
.venv/Scripts/python -m scripts.load_test              # 300 чекинов за 60 с + рассылка на 300
.venv/Scripts/python -m scripts.load_test --duration 600
```
Прогон идёт через настоящий диспетчер, Postgres и движок рассылок. Telegram заменён
поддельным API ([scripts/fake_telegram.py](scripts/fake_telegram.py)). В фазе рассылки он отвечает
429 на каждый 40-й запрос и 403 для пяти «заблокировавших». Прогон проверяет, что нет дублей
и потерь.

Последний результат:
- **чекин:** 300/300 уникальных, у каждого ровно один ответ «Ты отмечен», повторные апдейты отброшены;
- **рассылка:** 295 доставлено, 5 заблокировали, 0 дублей, 0 потерь, около 19 с (из них 7 с паузы на 429).

Фейковые участники: `python -m scripts.seed` (300 человек, 100 команд) или
`python -m scripts.seed --csv seed.csv` для `/import`.

## Структура
```
app/
  main.py          aiohttp: webhook, /health, страницы, API; запуск планировщика
  config.py        настройки из env (описаны в .env.example)
  db/              модели и подключение к Postgres
  bot/             диспетчер, middleware, фильтры ролей, клавиатуры, хендлеры
  services/        импорт, привязка, рассылки, сегменты, опросы, чекин, выгрузки, outbox
  workers/         планировщик под лидер-локом и периодические задачи
  web/             экран чекина, дашборд, Mini App, API для бота игр
  i18n/            тексты бота: ru.yaml, en.yaml
migrations/        миграции Alembic
scripts/           seed.py, fake_telegram.py, load_test.py
tests/             unit/ и integration/ (настоящий Postgres)
samples/           пример CSV заявок
.railway/          Railway Infrastructure as Code
```

## Обновление зависимостей
Диапазоны версий лежат в `pyproject.toml`, точные версии для образа — в `requirements.txt`.
Чтобы обновить:
1. поставить зависимости в чистый venv (`pip install -e .`);
2. прогнать тесты;
3. выполнить `pip freeze --exclude-editable > requirements.txt`.
